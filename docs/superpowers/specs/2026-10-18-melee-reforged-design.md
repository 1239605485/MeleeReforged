# MeleeReforged：木剑三连斩设计稿

日期：2026-10-18。状态：设计已确认；0.1.0 测试构建完成，手机实测待验证。

实施核对发现通用 PatchLib Hook 未完整转发非泛型 IL2CPP 方法的 MethodInfo，因此采用独立 Dobby 原生转发，所有包装显式保留隐藏参数。挂钩前校验匹配的运行时元数据。当前 KernelLoader 的清理回调不能否决卸载，模组先通过 Android 动态链接器固定自身生命周期；固定失败则不安装挂钩。更换二进制版本需要重启游戏。

## 目标与范围

创建公开 GitHub 仓库 MeleeReforged，制作 KernelLoader 原生模组，首个构建目标 Android arm64-v8a。以用户提供的 Terraria 1.4.5.8、TEFKernel 与 KernelLoader 资料为基准。第一版只接管原版木剑，做出明显不同的挥剑动作、青绿刀光和命中反馈，为后续近战武器提供可扩展基础。

成功标准：真实持剑动作发生变化；手、剑、轨迹与伤害位置一致；连续攻击形成三段；武器实体清晰；其他武器保持原有行为；手机加载、进图、连续攻击及重进世界均稳定。

不在首版范围：其他木材剑、全部近战武器、额外飞行剑气、新物品注册、伤害数值加强、联机同步完成声明、全屏后处理。联机环境在验证前不启用自定义接管。

## 方案选择

推荐：薄游戏适配层 + 独立攻击状态机 + 武器注册表 + 共享轨迹采样。动作、碰撞和特效读取同一份姿态快照。

备选一：仅叠加刀光。实现快，但无法满足改变攻击动作的目标。

备选二：每种武器各写完整挂钩。初期自由，后期容易重复接管和互相覆盖；不采用。

借鉴 tModLoader 对使用动作、命中框和近战效果的职责划分，不照搬其运行时 API 或整份模组代码。

## 模块边界

| 路径 | 职责与依赖 |
| --- | --- |
| src/bootstrap/ | 导出入口、初始化和清理；协调适配层及资源 |
| src/interop/ | 唯一允许直接访问游戏对象及挂钩的位置；方法签名校验、字段访问、绘制适配 |
| src/combat/ | 攻击状态机、时间推进、轨迹与姿态计算；不依赖游戏指针和绘制 API |
| src/weapons/ | 武器注册表、木剑配置；后续按攻击机制增加控制器 |
| src/collision/ | 从轨迹生成命中数据，衔接原版伤害与免疫流程 |
| src/render/ | 刀光、残影、粒子、命中闪光；仅消费姿态快照 |
| src/config/ | 特效质量和可选震动参数；默认关闭震动 |
| tests/ | 纯逻辑测试：连段、时间、轨迹、重置与伤害事件去重 |

首版不预先实现矛、连枷、悠悠球控制器，仅确保注册接口可选择不同控制器。每把武器配置包含物品 ID、控制器 ID、三段动作参数及特效主题；特殊武器行为通过独立控制器扩展，不让单个文件堆积数百个分支。

## 数据流与状态

游戏适配层读取玩家、当前物品、攻速、方向和使用状态，构造 AttackInput。状态机输出 AttackPose：attackId、连段索引、阶段、标准化进度、握持点、剑身角度、剑尖位置及有效伤害窗口。

动作绘制、轨迹采样与命中处理只读取相同 AttackPose；绘制调用不得推进攻击时间。每名玩家拥有独立状态，绝不以全局静态连段代替。attackId 单调更新，用于区分相邻攻击及限制一次性事件。

阶段为 Idle → Windup → Swing → Recovery。连续持有攻击按 1→2→3→1 循环。两次攻击之间空闲超过 0.6 秒重置为第一段。松开攻击时完成当前挥击，不强制执行下一段。切物品、死亡、世界退出或玩家失效立即清空状态与拖尾。攻击进行中朝向按该次攻击锁定，下一次攻击重新采样；朝向与重力翻转统一在坐标变换层处理。

## 木剑动作与视觉

| 段落 | 动作 | 视觉 |
| --- | --- | --- |
| 1 | 蓄力后斜下快斩 | 青绿窄弧、短残影 |
| 2 | 反手上挑 | 反向弧线、双层渐隐残影 |
| 3 | 短蓄力后重横斩 | 宽月牙、叶片碎光、命中闪光 |

每段基准总时长沿用木剑经游戏攻速计算后的攻击周期，按蓄力、挥击、收势划分：第一段 20%/45%/35%，第二段 15%/45%/40%，第三段 30%/35%/35%。这些是初始调参值，不是已验证的最终手感。伤害数值、暴击和击退仍由原版计算；第三段的重击感来自节奏与视觉，首版不额外加伤。

剑柄锚定手部握持点，纹理长度、旋转原点与实际木剑贴图一起核对。先实现正确动作与可见实体，再逐层叠加效果。分层顺序：背景柔光 → 轨迹和残影 → 武器实体（配合玩家遮挡关系）→ 前景火花。不得通过全局隐藏物品来消除原版重复绘制，只在已接管木剑的持握绘制范围内替换。

特效采用局部刀光、少量光照及粒子，不引入全屏模糊或扭曲。残影寿命起始 0.12 秒，第三段 0.18 秒。低/中/高质量限制每名玩家轨迹点为 12/20/28、活动粒子为 24/48/80，并设置全局粒子上限 320；超预算丢弃装饰粒子，不影响动作和命中。数值须以设备实测调整。

## 命中与原版兼容

第一版优先在已验证的原版近战伤害流程中替换木剑命中几何，保留原版伤害、免疫与击退逻辑。禁止同时执行一套原版伤害和一套自定义伤害。有效伤害窗口仅位于 Swing 阶段；重叠采样不应导致额外重复结算。

精确轨迹判定拟采用上一帧与当前帧剑身扫掠检测；具体接入位置必须通过实际方法体或反汇编确认。若只能安全调整矩形命中框，必须明确其几何精度限制，不能宣称实现精确弧形碰撞；不得以一块巨大矩形代替整个扇形并当成最终结果。

只识别注册表中的原版木剑，不改变物品总数，不批量修改 SetDefaults，不接管其他武器。无法验证关键签名、绘制资源或命中路径时，整体停止该武器接管，保留原版行为，记录一次诊断。

## 已核对证据与实施前检查

已核对：KernelLoader 的 mod-api/mod_core.h 提供 create_kernel_mod、init_mod、cleanup_mod；test-mod/mod.c 示范 PatchLib 类型/字段查找和前后置挂钩。includes/tefkernel/patchlib/method.h 明确前置回调 true 跳过原方法、false 继续原方法，并提供签名查询。

游戏 Source-1.4.5.8/PE/Assembly-CSharp/Terraria/Player.cs 中存在 itemRotation、itemLocation、ItemCheck_GetMeleeHitbox 和 ItemCheck_MeleeHitNPCs 声明，但检查到的方法体为空。声明和 RVA 不能证明安全调用；不将其偏移直接当作已验证 Android ABI。

实施前必须核对：两个 idump 的具体版本与目标平台；值类型参数和 out 参数封送；动作更新与持握绘制顺序；命中与免疫调用链；运行时挂钩卸载或停用能力；SpriteBatch 状态和玩家遮挡层；原版木剑 ID、纹理、握持原点。上述检查失败时停止相关功能，不累积猜测性补丁。

## 生命周期与性能

挂钩只安装一次，保存自身句柄；局部初始化失败时回滚自身已安装部分。清理时先停止事件进入，再移除自身挂钩和释放资源，不全局移除其他模组挂钩。必须确认框架卸载语义；不支持安全卸载时不声称支持热卸载。

游戏对象仅在确认有效的游戏线程和回调周期内访问，不跨世界保存裸指针。缓存稳定方法句柄；每帧不做反射查找，不为每个轨迹点分配内存。退出世界后清空玩家状态，绘制修改恢复原有状态。

## 验证与交付

纯逻辑检查覆盖：三段循环、攻速缩放、空闲超时、切物品重置、左右镜像、有效命中窗口和攻击事件去重。构建检查覆盖 Android AArch64 ELF、导出入口、打包元数据和过期文件。手机实测逐项确认：启动、进图、木剑动作、命中、连续攻击、移动跳跃、左右朝向、其他武器、暗处实体可见、重进世界与性能。

执行顺序：验证 ABI 和接入点 → 木剑动作及实体 → 命中联动 → 分层特效 → Android 构建及设备反馈。每阶段保留明确基线；用户实测失败先撤回失败改动再修正。

公开仓库只提交本模组代码、必要且允许再分发的依赖及授权信息；不上传游戏导出源码、IL2CPP dumps 或整包原版素材。构建成功与游戏实测通过分别报告，单机通过不代表联机可用。
